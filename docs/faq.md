# 常见问题（FAQ）

## 安全与隐私

### 你们能拿到我的 API Key 吗？

不能。API Key / Secret Key / Passphrase 保存在**你自己机器上**的配置里（`~/.okx/config.toml` 或本程序的配置文件），由 OKX 官方命令行工具在本地读取并签名请求。程序本身不上传、不打印、不记录密钥，也没有任何中心服务器代持你的凭证。

### 需要给提币权限吗？

**不需要，也不应该给。** 只勾选「读取」和「交易」两项即可。本程序不下单以外不做任何资金操作。

### 会不会偷偷调到我的主账户？

程序只能操作你配置了的那一个 API Key 对应的账户。强烈建议**单独开子账户**给本程序用，把风险隔离在一个小池子里。

## 收益与风险

### 能保证盈利吗？历史胜率多少？

**不能保证，也不做任何收益承诺。** 自动化交易在震荡、插针、流动性骤降等行情下都可能亏损，加杠杆会放大亏损。历史表现不代表未来结果，请只投入完全亏得起的资金。

### 最少要多少钱才能跑？

程序按「单笔名义金额」计算仓位。技术上用很小的金额也能跑，但金额过小会让手续费占比变高、且容易撞到交易所的最小下单量限制。建议先模拟盘验证逻辑，实盘第一笔用最小名义金额试。

### 亏损了谁负责？

你自己。本项目是工具，不构成投资建议，不提供代客理财，不承担交易结果。

## 使用

### 支持哪些平台？

Windows（本地 EXE）和 Linux（tar.gz + systemd）。macOS 未做适配。

### 支持现货还是合约？

以 USDT 本位永续合约为主，支持全仓/逐仓与双向持仓模式。

### 停掉程序，已经开着的仓位会怎样？

仓位留在 OKX 账户里，止盈止损单也已经挂在交易所侧，**不会因为程序退出而失效**。但主动的跟踪止盈、超时撤单、动态保护这些逻辑会停止运行。

### 改完配置为什么不生效？

策略主程序**只在启动时读取一次配置**，改完需要重启服务。例外是控制台上的「暂停开单 / 恢复开单」开关，它按轮询生效，不需要重启。

### 电脑关机 / VPS 重启会怎样？

程序停止运行，持仓与挂单留在交易所。需要 7×24 运行请用 Linux + systemd，并配置开机自启。

### 会跑多少个币？能只跑我指定的币吗？

默认扫描全市场永续合约并按信号筛选，同时支持币种白名单和排除名单。具体字段见 [安装与配置](install.md#5-配置说明)。

## 与 OKX AI Builder 的关系

### 这个项目和 OKX AI Builder Program 是什么关系？

本项目正在接入 OKX AI Builder Program：交易通过 OKX 官方命令行提交，并在下单时携带 Builder Code 用于返佣归因。**归因参数不影响任何交易逻辑**——带不带它，下单行为完全一致。

### 加了 Builder Code 我会多付手续费吗？

不会。你的手续费率由你的 VIP 等级决定，与是否携带 Builder Code 无关。

### 可以自己去掉这个参数吗？

可以，改成不用官方接入方式即可。但那意味着这个项目不再能获得平台的返佣支持，从而影响它的持续维护。

## 故障排查

### 程序启动了但一直不开单

常见原因（按概率排序）：

1. 没有满足条件的信号（大部分轮次本来就不该开单）
2. 已达每日 / 每轮开单上限或持仓上限
3. 当天该币已经开过（防重复规则）
4. 可用保证金低于配置的阈值
5. 成交额门槛、涨跌幅闸门等风控条件把候选拦掉了
6. 策略被自动或手动禁用

控制台与数据看板会显示每一轮的**拦截原因**，优先看那里。

### Windows 上控制台一直没有信号

先确认 Node.js 是 18 以上，并确认控制台是以 UTF-8 代码页启动的（旧版本在 GBK 代码页下会把返回的 JSON 解坏，表现为「每一轮都失败、永远不开单」）。升级到最新版即可。

### 报 `--aiBuilderCode is not supported`

说明本机的 OKX 命令行版本过旧。升级：

```bash
npm install -g @okx_ai/okx-trade-cli
```

（本程序的归因逻辑带降级保护：检测到命令行不支持时会自动跳过该参数，**不会因此导致下单失败**。）
